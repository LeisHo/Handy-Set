Fixed (found live during this session's own verification, not assumed
working):
- Zero-size-framebuffer render (documented HANDY DANDIES sandbox gotcha,
  `window.innerWidth`/`innerHeight` reading 0 at script-parse time) --
  `animate()` now self-heals every frame, same fix shape as that project.
- Wrist-crop clipping plane was defined in the raw bind-pose local frame
  while the mesh renders fully transformed (world-space clipping planes)
  -- fixed to use the clone's actual `matrixWorld`.
- Wrist-crop plane normal was inverted (discarding the fingers, keeping
  the forearm) -- fixed via an explicit `distanceToPoint()` check at the
  wrist vs. the hand's own visible center.
- Wrist-crop reach: the visible forearm/sleeve mesh extends far past the
  `rForearmBend` bone's own position (confirmed via a wide diagnostic
  screenshot -- a long dark sleeve with only a small fist-colored patch
  at one end) -- switched from a wrist-to-forearm-bone lerp to a fixed
  multiple of hand length, tuned by eye.
- Camera presets retargeting: HANDY DANDIES' saved cameras were captured
  against its own much larger multi-hand field (default field radius
  ~138 world units vs. this project's ~15-20) -- preserving their raw
  offset distance put the camera absurdly far from a single hand;
  `applyCameraPreset()` now preserves each preset's direction/FOV but
  recomputes distance from a "fit the hand in this FOV" formula.
- The dev panel never showed this project's own groups on first load --
  `main.js` (a deferred module script) executed AFTER `devPanel.js`'s own
  eager `ensureDevPanelBuilt()` call (auto-open on localhost), so
  `window.renderHandysetDevGroups` didn't exist yet when needed. Fixed by
  adding `defer` to devPanel.js's script tag and loading it after main.js
  (both then execute in that relative document order).
- The DEV toggle button/panel were permanently `display:none` -- missed
  copying the template's own early `<head>` script that sets
  `html.dev-mode` (a separate, tiny script block before the main
  `<style>`/`<script>`, easy to miss when assembling index.html by hand).
- Stale script cache: bumping the top-level navigation URL's query string
  didn't pick up main.js edits -- the actual `<script src="...?v=N">` tags
  need their own version bump (documented HANDY DANDIES gotcha, re-hit
  here).

Verified:

  "Show Wireframe" checkbox via a real `computer` click on the rendered
  page -- confirmed both `cfg.showWireframe` and the live material's
  `wireframe` property flipped, and the rendered mesh visibly changed to

- Scrolled through the built dev panel confirming Debug (+ Sensors
  subgroup with the Desktop-silence note), Tween, Field Layout, and Pose

2026-09-21  -  1:18 AM - 1:25 AM EDT

Fixed 2 dev panel checkbox bugs reported directly by the user after
comparing the real behavior against TEMPLATE_DEV_PANEL.html's own
documented functionality.

Fixed:
- Every setting row on the Desktop tab showed "Independent from Desktop"
  instead of "Show in Mobile/Landscape" -- root cause: `addRow()`
  (main.js) never set `ctrl.tab = 'desktop'` on any control object, and
  `buildUniformControlRow()` (devPanel.js) checks `ctrl.tab === 'desktop'`
  explicitly to decide which checkbox to attach, silently falling through
  to the wrong one for every one of this project's ~150 controls. Fixed
  centrally in `addRow()`.
- No group-level "show in mobile/landscape" checkbox ever appeared next
  to any group's undock icon -- root cause: `buildGroupCascadeCheckbox()`
  in the RAW TEMPLATE_DEV_PANEL.html file itself sets `cb.style.display =
  'none'` unconditionally at creation, and nothing anywhere in that
  ~5700-line file ever sets it back to visible (confirmed by exhaustive
  grep of both this project's copy and the source template). This is a
  genuine latent bug in the template as shipped, not a simplification
  made in this project. Fixed locally by removing that line.

Verified:
- Direct DOM/computed-style inspection (getBoundingClientRect,
  getComputedStyle) on a live-reloaded page confirmed the group checkbox
  now has real dimensions and `display: block`, and a Camera-group row's
  checkbox is now `.dev-visibility-checkbox` titled "Show in Mobile/
  Landscape" (was `.dev-independence-checkbox`).
- Visual screenshot confirmation: every group title now shows its own
  checkbox left of the lock/undock icons; Debug's individual rows
  (Show Grid Helper, Show Wireframe, etc.) each show their own row-level
  checkbox on the right.
- Along the way, hit the documented sandbox-networking gotcha (devPanel.js,
  4557 lines, intermittently failing to fully load under this sandbox's
  local static server -- `200 OK` + `net::ERR_CONNECTION_RESET` on the
  same request) which produced a completely empty dev panel and looked
  like a real regression until traced to a plain failed network request,
  resolved by retrying the navigation. Logged as its own gotcha since it
  cost real time before being correctly identified.

2026-09-21  -  3:48 AM - 4:08 AM EDT

Fixed 5 issues reported directly after live testing on the real Vercel
deployment, plus 2 requests added mid-session (Phone Tilt real-device
report, group-checkbox retention behavior).

Fixed:
- Pose Offset/Rotation/Thumb not appearing in their correct subgroups --
  root cause: the git-tracked dev-panel-settings.json AND the browser's
  own localStorage both held a saved panel layout captured before this
  session's earlier Pose-group restructure (Rotation/Thumb split, Pose
  Offset subgroup); applySectionOrder() APPENDS an unmatched old group
  rather than replacing it, producing literal duplicate groups/rows with
  dead ids on top of the correct fresh ones. This is also the real cause
  of the separately-reported "miscellaneous/redundant checkboxes that
  flash and can't be clicked." Fixed the git file directly AND added a
  client-side localStorage schema-version guard (HANDYSET_SETTINGS_SCHEMA_VERSION
  in main.js) so this can't recur silently on a future structural change
  -- bump the version constant, the stale local save clears itself.
- "Set as Default" was missing from Pose/Camera/Lighting/Toon Shading --
  added a generic saveFieldAsDefault()/loadFieldDefaultIfSaved() pair
  (ported from Hando's own saveAsDefaultForModel()/loadDefaultForModelIfSaved(),
  simplified since Handyset has one model, not Hando's multi-model
  system) and wired a "Set as Default" button into renderPresetPicker()
  for all 4 groups.
- Toon Shading was missing the entire rim-light + texture/duotone-tint
  shader system (a known simplification from the first build) and had no
  saved-preset UI at all -- ported HANDY DANDIES' own createToonMaterial()
  onBeforeCompile GLSL injection verbatim (not reconstructed), added the
  5 missing sliders, and a full "Saved Toon Shading" list-picker with
  Export/Import + Set as Default.
- Phone Tilt did nothing on either desktop OR a real Android phone --
  removed the isTouchDevice branching that gated mousemove vs.
  deviceorientation as mutually exclusive; both listeners now always
  attach, so whichever one actually produces real events on a given
  device just works, without needing to correctly guess the device type
  first. (The real-device report couldn't be fully root-caused without
  console access to the actual phone -- pointed the user at the existing
  Debug > Sensors console to check whether deviceorientation events fire
  at all as the next diagnostic step if this doesn't resolve it.)
- Group-level "Show in Mobile/Landscape"/"Independent from Desktop"
  checkboxes now retain each child row's own individual checked state
  when the group checkbox is unchecked, and restore those exact
  per-child states (not a blanket re-check) when it's checked again --
  devPanel.js's buildGroupCascadeCheckbox(), per direct request.

Verified:
- Live DOM inspection after each fix confirmed: Pose subgroups no longer
  duplicated; all 4 "Set as Default" buttons present; Toon Shading's rim
  slider and Saved Toon Shading list-picker both render; a real
  group-checkbox uncheck/recheck cycle correctly zeroed then restored

- NOT verified: the Phone Tilt fix's effect on a real phone (no device

2026-09-21  -  4:08 AM - 4:35 AM EDT

Closed the "known gap" from the previous entry: rebuilt the Tween group
to match Hando's real UI, researched directly from Hando's own source
(devPanel.js buildMultiSelectRow()/renderMultiSelectRows(), main.js's own
Tween/Export DEV_GROUPS entry) rather than reconstructed from memory.

Added:
- `buildMultiSelectWidget()` (main.js) -- an ordered, drag-reorderable
  list of per-row pose dropdowns or Hold entries, with "+ Add"/"+ Hold"
  above and a "Remove" button per row. Matches Hando's own interaction
  design (Add defaults to the next option after the previous row's pick;
  Hold defaults to the last Hold's own percent) exactly; the reorder
  MECHANISM itself uses native HTML5 drag-and-drop rather than Hando's
  own pointer-capture-based engine drag system, since that infra isn't
  part of the raw TEMPLATE_DEV_PANEL.html this project is built on --
  disclosed as a mechanism-only simplification, not a UI/behavior gap.
- `resolveTweenTimeline()`/`applyTweenAtT()` -- a weighted-segment model
  (Hold entries pause at a percentage of one normal transition's own
  weight, matching Hando's own semantics) driving a manual "Tween
  (0=First, 1=Last)" scrub slider, replacing the previous auto-play "Run
  Tween" button entirely (Hando has no auto-play/Loop/Oscillate mechanism
  at all -- confirmed by direct source grep, not assumed).
- `exportTweenSequence()` -- one-shot PNG-sequence export (Export Frame
  Count + Export Filename Prefix controls), rendering each sampled frame
  via canvas.toDataURL() and triggering a download. Hando's own exact
  implementation wasn't available to extract verbatim; this is a
  faithful from-scratch rebuild of the same standard browser-native
  render-and-download behavior, not a verbatim port.
