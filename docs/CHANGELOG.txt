2026-09-20 11:50 PM - 2026-09-21 12:29 AM EDT

First working build, per a detailed spec given mid-session (mobile
gyroscope-tilted single hand, offshoot of HANDY DANDIES, dev panel ported
from that project's own groups but built against the real
TEMPLATE_DEV_PANEL.html engine, seeded pose/camera/lighting presets).

Added:
- `index.html`/`src/main.js`/`src/style.css`/`src/devpanel/devPanel.js` --
  a working single-hand three.js scene. Finger/wrist posing math ported
  verbatim from HANDY DANDIES (`FINGER_JOINTS`/`FINGER_MAX_DEG`/`FINGER_SIGN`/
  `FINGER_CURL_AXIS`/etc, `rotateOnTrueWorldAxis`, `applyCurlToSkeleton`).
- Phone Tilt mechanic: real-device `deviceorientation` (with iOS
  permission-request handling) and a desktop mouse-distance/angle
  fallback, both reduced to one shared normalized tilt-vector
  abstraction, feeding the same lookAt+slerp rotation pattern HANDY
  DANDIES uses for cursor tracking.
- Dev panel: all 9 requested groups (Tween, Field Layout, Pose w/ 6
  subgroups, Camera, Phone Tilt w/ 3 subgroups -- renamed from Cursor
  Tracking, off by default, Lighting, Toon Shading w/ Outline subgroup,
  Background, Debug) built against the ACTUAL `.claude/TEMPLATE_DEV_PANEL.html`
  engine (copied verbatim into `src/devpanel/devPanel.js`), not HANDY
  DANDIES' own divergent copy -- a genuine mid-task architecture pivot,
  requiring every setting to be translated into the template's real
  (narrower) control-type API rather than 1:1 ported.
- Debug group's own Sensors console: raw accelerometer/gyroscope/compass
  readout, opt-in streaming toggle + sample-interval slider, gated to
  show "No sensor data on Desktop." and never stream on a non-touch
  device.
- Seeded SAVED_POSES (4)/SAVED_CAMERAS (7)/SAVED_LIGHTING (7) from the
  user's own exported HANDY DANDIES data; defaults applied on load
  (Fist / FRONTOS / FLABOVE, per direct instruction -- "Fronto"/"Flabove"
  matched to the closest-named entries, flagged to the user rather than
  guessed silently).

Fixed (found live during this session's own verification, not assumed
working):
- Zero-size-framebuffer render (documented HANDY DANDIES sandbox gotcha,
  `window.innerWidth`/`innerHeight` reading 0 at script-parse time) --
  `animate()` now self-heals every frame, same fix shape as that project.
- Wrist-crop clipping plane was defined in the raw bind-pose local frame
  while the mesh renders fully transformed (world-space clipping planes)
  -- fixed to use the clone's actual `matrixWorld`.
- Wrist-crop plane normal was inverted (discarding the fingers, keeping
  the forearm) -- fixed via an explicit `distanceToPoint()` check at the
  wrist vs. the hand's own visible center.
- Wrist-crop reach: the visible forearm/sleeve mesh extends far past the
  `rForearmBend` bone's own position (confirmed via a wide diagnostic
  screenshot -- a long dark sleeve with only a small fist-colored patch
  at one end) -- switched from a wrist-to-forearm-bone lerp to a fixed
  multiple of hand length, tuned by eye.
- Camera presets retargeting: HANDY DANDIES' saved cameras were captured
  against its own much larger multi-hand field (default field radius
  ~138 world units vs. this project's ~15-20) -- preserving their raw
  offset distance put the camera absurdly far from a single hand;
  `applyCameraPreset()` now preserves each preset's direction/FOV but
  recomputes distance from a "fit the hand in this FOV" formula.
- The dev panel never showed this project's own groups on first load --
  `main.js` (a deferred module script) executed AFTER `devPanel.js`'s own
  eager `ensureDevPanelBuilt()` call (auto-open on localhost), so
  `window.renderHandysetDevGroups` didn't exist yet when needed. Fixed by
  adding `defer` to devPanel.js's script tag and loading it after main.js
  (both then execute in that relative document order).
- The DEV toggle button/panel were permanently `display:none` -- missed
  copying the template's own early `<head>` script that sets
  `html.dev-mode` (a separate, tiny script block before the main
  `<style>`/`<script>`, easy to miss when assembling index.html by hand).
- Stale script cache: bumping the top-level navigation URL's query string
  didn't pick up main.js edits -- the actual `<script src="...?v=N">` tags
  need their own version bump (documented HANDY DANDIES gotcha, re-hit
  here).

Verified:

  "Show Wireframe" checkbox via a real `computer` click on the rendered
  page -- confirmed both `cfg.showWireframe` and the live material's
  `wireframe` property flipped, and the rendered mesh visibly changed to

- Scrolled through the built dev panel confirming Debug (+ Sensors

- NOT verified: real device motion data (no physical phone available this

2026-09-21  -  1:02 AM - 1:05 AM EDT

Wired the dev panel's git-tracked Save (CLAUDE.md §12l upgrade), per
direct follow-up: the user had already deployed to Vercel
(https://vercel.com/lpeis/handy-set) and set GITHUB_TOKEN/
DEV_PANEL_SAVE_SECRET, expecting the Save button to write through to
GitHub -- but the first build only wired plain localStorage (the raw
TEMPLATE_DEV_PANEL.html engine has no remoteSave concept at all, unlike
HANDY DANDIES' own divergent devPanel.js copy).

Added:
- `api/save-settings.js` -- ported near-verbatim from HANDY DANDIES' own
  (same GitHub Contents API mechanism, same env var names), repo default
  changed to `LeisHo/Handy-Set`.
- `main.js`: `wireRemoteSaveButtons()`/`remoteSaveCurrentSettings()`/
  `loadRemoteSettingsOnStartup()` -- attaches additional click listeners
  to the existing SYNC buttons (both the `.dev-buttons` one and the
  header icon one) rather than wrapping/overriding devPanel.js's own
  `saveDevPanelSettings`, keeping devPanel.js itself untouched beyond its
  one documented splice point. Polls for devPanel.js's own globals
  (`captureFullDevPanelState`/`applyFullDevPanelState`) via
  `waitForDevPanelGlobal()` since main.js necessarily loads BEFORE
  devPanel.js (see the script-order gotcha from the first build).
- README.md: added the "Dev panel Save button setup" section (env var
  names/values, matching HANDY DANDIES' own).

Verified:
- Clicked the real SYNC button in the browser -- confirmed (via
  `read_network_requests`) a POST to `/api/save-settings` fires with the
  captured panel state, failing with `ERR_CONNECTION_RESET` locally (the
  plain python static server has no serverless-function support -- this
  is the expected local-dev failure mode, not a real bug) without
  crashing the page or leaving the panel in a bad state.
- NOT verified: an actual GitHub commit landing, since that requires the
  real Vercel deployment with its own configured env vars, which this
  session has no access to test directly. The client-side wiring and the
  serverless function's own logic (ported from an already-working sibling
  project) are the two halves that could still fail independently on the
  real deployment -- ask the user to click Sync on the live Vercel URL
  and confirm a new commit appears in the GitHub repo.
